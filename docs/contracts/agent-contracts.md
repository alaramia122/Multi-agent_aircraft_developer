# Контракт инженерных AI-агентов

## Назначение

Контракт фиксирует границу между будущим оркестратором/Yandex AI Studio и Engineering Gateway.

Агент получает версионированную задачу и контекст, а возвращает предложение и/или evidence references. Агент не получает capability L3 и не является источником истины для инженерных артефактов.

## Роли

Контракт определяет роли:

- chief_engineer
- requirements
- system_architect
- safety
- software_architect
- verification
- configuration
- reviewer
- cost

Роль определяет ответственность агента, но не выдаёт ему Gateway-разрешения.

## Задача агента

AgentTask содержит:

- contract_version;
- уникальный task_id;
- role;
- kind: analyze, propose или review;
- ограниченный objective;
- ссылки на workspace, baseline, change_request;
- зафиксированные версии исходных систем;
- список разрешённых идентификаторов внешних инструментов;
- входные данные.

Неизвестные поля запрещены. Контракт сейчас имеет версию 1.0.

## Результат

AgentProposal содержит:

- идентификатор исходной задачи;
- роль;
- состояние completed, blocked или failed;
- краткое резюме;
- предлагаемые элементы и связи;
- ссылки на evidence;
- запрошенные инструменты;
- причины блокировки;
- метаданные.

В контракте отсутствует поле approved и отсутствует операция утверждения. L3 остаётся исключительно человеческой операцией Gateway.

## Внешние инструменты

allowed_tool_ids и requested_tool_ids являются только идентификаторами контрактов инструментов. Они не дают агенту произвольного доступа к системе.

Следующий этап должен определить отдельный Connector/Tool Registry с:

- описанием инструмента;
- интерфейсом;
- trust level;
- разрешёнными действиями;
- ограничениями side effects;
- привязкой к проекту/assurance profile;
- журналированием вызова.

AI Studio не должен обращаться к инженерным системам напрямую: вызовы проходят через MCP/Gateway и его authorization boundary.

## Что пока не реализуется

Этот контракт не создаёт:

- runtime агента;
- AI Studio Agent/Workflow конфигурацию;
- автоматическую оркестрацию;
- Tool Registry;
- LLM-based authorization;
- L3 capability.

Это следующий слой поверх уже стабилизированного Gateway.
