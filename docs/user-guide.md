# Руководство пользователя инженерного портала

Адрес staging: <https://51-250-6-236.sslip.io/human/>. Это рабочая
предварительная версия системы. Зелёная отметка на шкале жизненного цикла
обозначает состояние, подтверждённое данными Gateway; остальные этапы пока
показывают намеченный процесс.

## 1. Вход и черновик

1. Нажмите **«Войти через Keycloak»** и войдите своей учётной записью.
2. В разделе **«Структура проекта»** введите название, цель и известные
   ограничения. Нажмите **«Создать черновик»**.
3. Выберите сохранённый черновик. Проверьте его версию и SHA-256. Это исходный
   текст автора, а не сформулированное и проверенное инженерное требование.
   Создание черновика не запускает агентов и не утверждает конструкцию.

Черновики видны только их автору. Сейчас они неизменяемые (версия 1). Если
исходная цель существенно поменялась, создайте новый черновик; редактор версий
исходного задания пока не реализован.

## 2. Диалог с Alice и память

Нажмите **«Обсудить с Alice»** у нужного черновика или выберите его и перейдите
к чату. При отправке сообщения Alice получает выбранный исходный черновик и
часть сохранённых реплик. Над диалогом показаны число сохранённых реплик,
точное число реплик, переданных в последний запрос, версия и краткий хэш
черновика. После обновления страницы журнал загружается из PostgreSQL.

Полный журнал хранится по проекту, но в один запрос модели передаются не более
24 последних реплик в пределах 24 000 символов. Раскройте подсказку
**«Какие прошлые сообщения получает Alice?»** под индикатором. Старые записи
можно читать в интерфейсе, однако вне окна контекста модель может не учитывать
их при новом ответе. Для важного раннего решения повторите его в текущем
сообщении. Диалог без выбранного проекта не сохраняется. Разговоры, состоявшиеся
до включения серверного журнала, невозможно восстановить с сервера.

Alice помогает уточнить исходные сведения и предложить следующий шаг. Её
текст не является автоматически созданным требованием, записью в StrictDoc,
моделью Capella, независимым review или решением L3.

## 3. Что происходит после уточнения замысла

Сейчас **нет кнопки перехода из черновика в инженерный проект**. Нужно
реализовать создание проекта с выбранным Standard Profile, отдельным Git
источником, чистыми StrictDoc и Capella источниками и OpenProject Change
Request. Это зафиксировано в [задаче #22](https://github.com/alaramia122/Multi-agent_aircraft_developer/issues/22).
Пока переход не выполнен, шкала остаётся на стадии «Замысел». Ответ Alice
не подменяет фактическую инициализацию.

Для уже созданной инженерной рабочей области можно ввести её UUID, загрузить
пакет, проверить состав изменений, источник, версии, validation и
reconciliation evidence. UUID не создаётся при сохранении черновика.

## 4. Исходная версия, рабочая область и baseline

| Объект | Что означает | Можно ли менять |
| --- | --- | --- |
| Черновик | Исходная цель и ограничения, сообщённые человеком | Текущая запись неизменяема; создайте новую редакцию как новый черновик до реализации версионирования |
| Чистый стартовый источник | Пустая валидная модель и документы для нового проекта, без проектных утверждений | Изменения подготавливаются в изолированной рабочей области |
| Рабочая область | Предлагаемые требования, архитектура, связи и evidence, привязанные к версии источника и Change Request | Уполномоченный L2 может изменять до проверки; после изменения прежние evidence должны проверяться заново |
| Утверждённый baseline | Фиксированный Git commit/tag и версии внешних систем после проверки и личного L3 | Не редактируется; новая версия получается через новый Change Request и новую рабочую область |

Для нового проекта логично иметь **чистую исходную версию**, от которой строится
первое предложение. Называть её утверждённым baseline нельзя: тогда создаётся
ложное впечатление, что требования и модель уже проверены. Первый настоящий
baseline появляется только после сохранения содержания, детерминированных
проверок, reconciliation, независимого review и решения человека с ролью L3.

## 5. Проверка и личное решение

В разделе **«Независимая проверка»** загрузите пакет по UUID и сверьте
оригинальные артефакты, версии и хэши. Независимый reviewer указывает причину
и URI проверяемого свидетельства. Утверждение baseline доступно только человеку
с ролью L3, отдельно от AI и сервисных токенов. Система должна отклонить
решение при устаревшей validation или reconciliation evidence. Не нажимайте
«Утвердить» лишь по рекомендации Alice.

Ваша текущая учётная запись `Alaramia` имеет роль предложения (`gateway-propose`),
поэтому не выполняет L3. Это ожидаемое разделение ролей.
